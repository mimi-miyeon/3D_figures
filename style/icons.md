# 아이콘 레지스트리

만든 아이콘 목록이다. 새 아이콘 요청이 오면 **이 파일을 먼저 읽는다.**

1. 이미 있는 아이콘이면 → 아래 슬롯 블록을 그대로 복사해 재생성한다
2. 새 아이콘이면 → **앵커 아이콘 이미지를 레퍼런스로 첨부**하고 `templates/icon.md` 골격으로 만든다
3. 만든 뒤 아래 표와 슬롯 블록에 기록한다

스타일 규칙은 `style/icon-style.md`, 골격은 `templates/icon.md`.

## 세트 고정값 (모든 아이콘 공통 — 문장을 그대로 복사해 쓴다)

이 값들이 어긋나면 세트가 무너진다. 아이콘마다 **똑같은 문장**으로 넣는다.

| 항목 | 프롬프트 문구 |
|---|---|
| 프레임 점유율 | `filling about 65% of it` |
| 3D 기울기 | `slight 3D tilt rotated about 15 degrees` |
| 최소 두께 | `No part is thinner than one tenth of the icon's width.` |
| 조명 | `soft studio lighting from the upper left` |
| 배경 | 배경 C (밝은 배경) — `templates/icon.md` 골격 참조 |
| 짝 파츠 비율 | `a size ratio of about 1 : 0.95 between any paired parts` |

### 12종 샘플 시트 — `작업중` ★ 현재 스코프

**지금 만드는 것은 이 한 장뿐이다.** 백로그의 나머지는 아직 만들지 않는다.

스타일이 다양한 형태를 견디는지 검증하는 시트로, 어려운 케이스를 골고루 넣어
**실패 유형을 먼저 드러내는 것**이 목적이다.

| # | 아이콘 | 검증하려는 것 |
|---|---|---|
| 1·2 | home 선 / home 채움 | **선/채움 2상태**가 튜브 vs 솔리드로 구분되는가 |
| 3 | progress (막대그래프) | **얇은 막대**가 두툼한 덩어리로 번역되는가 |
| 4·5·6 | plus / check / x | 단순 기하 형태의 기본 품질 |
| 7 | play | 삼각형 모서리가 둥글게 유지되는가 |
| 8 | pencil | **가늘고 긴 형태**가 부러지지 않는가 |
| 9·10 | momentum-strong / fading | **꽉 참 vs 빔** 대비 + 세이지 액센트 |
| 11 | streak (불꽃) | 유기적·비정형 형태 |
| 12 | 읽기 (책) | 카테고리 아이콘 대표 |

> 이 12개가 통과하면 백로그의 나머지도 같은 방식으로 확장 가능하다고 본다.
> 실패한 유형이 있으면 **그 유형의 규칙을 먼저 고치고** 다음으로 넘어간다.

**⚠️ 한 장에 여러 개 생성할 때:** 그리드 셀을 집합으로 서술하면
(`12개가 4x3으로 배열`) 모델이 셀을 비우거나 합친다.
→ **셀 하나마다 한 줄씩 개별 지정**하고, 마지막에 **덧셈 문장**(`4 + 4 + 4 = 12`)을 넣는다.

## 새 아이콘 추가 절차

1. `style/icon-style.md` F의 용도별 규칙 확인 (기능 아이콘인지 카테고리 아이콘인지)
2. **앵커 아이콘 이미지를 레퍼런스로 첨부** + `templates/icon.md` 골격에 슬롯을 채워 생성
3. **32px로 줄여서 읽히는지** 확인 — 이게 합격 기준이다
4. 확정되면 `assets/icons/final/{이름}-v{차수}-{YYYYMMDD}.png`로 저장
5. 위 표와 슬롯 블록에 기록
6. 3개 이상 모이면 **한 줄로 나란히 놓고 본다.** 크기·기울기·두께가 어긋난 것만 재생성
